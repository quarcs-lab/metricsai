# 2026-05-15 — EN/ES Language Toggle for Project Website

## Session Goal

Add a small Spanish/English language toggle to the public-facing project website (`index.html`, then `tutors.html`). The user wants Spanish-speaking visitors to be able to read a basic overview of the project in Spanish; English remains the default. Future sessions will extend the same pattern to other pages (`videos.html` first).

## What shipped today

1. **`index.html`** — full EN/ES toggle. 63 translatable strings tagged with `data-i18n`. Spanish dictionary covers nav, hero, About/Why metricsAI, 4 feature cards, podcast intro, curriculum + 4 part titles, books, authors heading, More Resources, footer (acknowledgments, datasets, license, disclaimer, help-improve, copyright). Chapter blurbs, resource cards, and author bios deliberately stay English per the "basic overview" scope.
2. **`tutors.html`** — full EN/ES toggle at the deepest scope. 97 translatable strings: nav, hero, featured *Learning Coach* card, all 8 grid tutor cards (description + 4 tags + sample `Try:` prompt + `Best for:` line + `Chat` CTA), "Powered by" line, "How It Works" 3-step section, footer. Page `<title>` and `<meta name="description">` also swap. Tutor product names (e.g. *Learning Coach*) stay English because they match the actual Gemini Gem product names.
3. **No new files.** All code is inline in each HTML file. No build step, no external translation files.

## The Pattern — read this when extending to a new page

The implementation is intentionally small and uniform. Six pieces, in this order:

### 1. Desktop navbar button

Insert immediately **after** the dark-mode `<button>` and **before** the mobile-menu hamburger:

```html
<button onclick="toggleLanguage()" class="text-slate-600 dark:text-slate-300 hover:text-brand-600 dark:hover:text-brand-400 transition-colors flex items-center gap-1" title="Switch language / Cambiar idioma" id="languageToggle">
    <i class="fa-solid fa-language text-lg"></i>
    <span class="text-xs font-semibold" id="languageLabel">EN</span>
</button>
```

### 2. Mobile menu row

Append at the bottom of `#mobileMenu`:

```html
<div class="pt-3 border-t border-slate-200 dark:border-slate-700">
    <button onclick="toggleLanguage()" class="w-full flex items-center justify-center gap-2 py-2 rounded-lg bg-slate-50 dark:bg-slate-800 hover:bg-slate-100 dark:hover:bg-slate-700 border border-slate-200 dark:border-slate-600 text-slate-600 dark:text-slate-300 font-medium transition-colors">
        <i class="fa-solid fa-language text-lg"></i>
        <span data-i18n="nav.language.label">Language</span>:
        <span id="languageLabelMobile" class="font-semibold">EN</span>
    </button>
</div>
```

### 3. Tag translatable elements with `data-i18n="key"`

- The element's **English content stays as the HTML default** — that is the fallback when JS is disabled, when a translation is missing, and when the user toggles back to EN.
- For rich content (links, `<strong>`, `<i>` inline), tag the **outer block** with `data-i18n` and put the full HTML (including `<a>` tags) in the Spanish dictionary value. The swap uses `innerHTML`, so inline HTML in translations is fine.
- For text fragments that share a wrapper with icons, wrap **only the translatable text** in a `<span data-i18n="...">`. Don't tag the parent if it has icons or buttons that shouldn't be re-rendered.
- Reuse keys across pages when the Spanish is identical (e.g. `nav.about`, `nav.podcasts`, `nav.language.label` are used by both `index.html` and `tutors.html`).

### 4. Inline `<script>` — paste right after the dark-mode IIFE

```javascript
const translations = {
    es: {
        'nav.about': 'Acerca de',
        // ... etc.
        'document.title': 'Spanish title here'
    }
};

function applyLanguage(lang) {
    document.documentElement.lang = lang;
    document.querySelectorAll('[data-i18n]').forEach(function(el) {
        if (typeof el.dataset.i18nOriginal === 'undefined') {
            el.dataset.i18nOriginal = el.innerHTML;
        }
        var key = el.dataset.i18n;
        if (lang === 'es' && translations.es[key] !== undefined) {
            el.innerHTML = translations.es[key];
        } else {
            el.innerHTML = el.dataset.i18nOriginal;
        }
    });

    // Page title
    if (!window.__originalTitle) window.__originalTitle = document.title;
    if (lang === 'es' && translations.es['document.title']) {
        document.title = translations.es['document.title'];
    } else {
        document.title = window.__originalTitle;
    }

    // Visible language code on toggle buttons
    var code = lang === 'es' ? 'ES' : 'EN';
    var lbl = document.getElementById('languageLabel');
    var lblM = document.getElementById('languageLabelMobile');
    if (lbl) lbl.textContent = code;
    if (lblM) lblM.textContent = code;

    localStorage.setItem('language', lang);
}

function toggleLanguage() {
    var current = localStorage.getItem('language') === 'es' ? 'es' : 'en';
    applyLanguage(current === 'es' ? 'en' : 'es');
}

// Initialize on load (English is default).
(function() {
    var saved = localStorage.getItem('language');
    var lang = saved === 'es' ? 'es' : 'en';
    if (document.readyState === 'loading') {
        document.addEventListener('DOMContentLoaded', function() { applyLanguage(lang); });
    } else {
        applyLanguage(lang);
    }
})();
```

### 5. Optional page-specific extras

- **Meta description swap** (already used in `tutors.html`). Add this block inside `applyLanguage` after the title-swap block:
  ```javascript
  var metaDesc = document.querySelector('meta[name="description"]');
  if (metaDesc) {
      if (!metaDesc.dataset.i18nOriginal) metaDesc.dataset.i18nOriginal = metaDesc.content;
      if (lang === 'es' && translations.es['document.description']) {
          metaDesc.content = translations.es['document.description'];
      } else {
          metaDesc.content = metaDesc.dataset.i18nOriginal;
      }
  }
  ```
- **JS-rendered content** (e.g. resource filter chips on `index.html`): the renderer reads `document.documentElement.lang` and picks an English or Spanish label. After toggling, `applyLanguage` calls the renderer again so the new language wins. Example pattern in `index.html` lines around `renderFilterPills` — it picks `cat.labelEs` vs `cat.label` based on `document.documentElement.lang`.
- **Hero typing animation** (`index.html` only): the typed element carries `data-typed-en="..."` and `data-typed-es="..."`. The animation IIFE reads `document.documentElement.lang` on first run to pick the word. `applyLanguage` also has a small block that swaps the already-typed text if the animation has finished, so post-paint toggles work without re-typing.

### 6. Cross-page persistence

All pages share `localStorage.setItem('language', ...)`. This is intentional — a user who toggles to Spanish on `index.html` lands in Spanish on `tutors.html` and vice versa. **Do not invent a new key**.

## Conventions you must follow when adding new keys

- **English source-of-truth** lives in the HTML. The Spanish dictionary is purely an override.
- **Key naming:** dotted lowercase, namespaced by section. `nav.about`, `hero.subtitle`, `tutors.card.<slug>.desc`. Slugs already in use for tutor cards: `case`, `socratic`, `exam`, `analogy`, `code`, `debate`, `visual`, `research`. Featured Learning Coach uses the `tutors.featured.*` namespace.
- **Reuse keys across pages** when the English is identical (`nav.*`, `nav.language.label`, `footer.copyright`). The Spanish strings get duplicated across each page's inline dictionary — this is the price of having no build step. Don't try to consolidate.
- **Rich content in values is OK** because we swap `innerHTML`. But the source of Spanish strings is hardcoded JS we wrote ourselves, so XSS is not a concern.
- **Anything kept English on purpose** (proper nouns, technical terms, external link URLs) gets **no** `data-i18n` attribute. Examples already locked in: 17 chapter titles + their blurbs (index), the 40+ resource cards (index), author bios (index), the 9 tutor product names (tutors), sample Try-prompt monospace strings on `index.html` resource cards but NOT on `tutors.html` (where the user explicitly opted to translate them).

## How to verify after a change

After editing, run this from the repo root to catch missing/orphan keys:

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('PATH/TO/FILE.html','utf8');
const used = new Set();
const re=/data-i18n=\"([^\"]+)\"/g;
let m;
while ((m=re.exec(html))) used.add(m[1]);
const block = html.match(/const translations = \{[\s\S]*?\};/)[0];
try { eval('(function(){'+block+';return translations;})()'); console.log('parses OK'); }
catch(e) { console.log('PARSE ERROR:', e.message); process.exit(1); }
const defined = new Set();
const re2=/'([\w.]+)':\s*'/g;
while ((m=re2.exec(block))) defined.add(m[1]);
const missing=[...used].filter(k=>!defined.has(k) && k!=='key');
const orphan=[...defined].filter(k=>!used.has(k) && k!=='document.title' && k!=='document.description');
console.log('used:', used.size, 'defined:', defined.size, 'missing:', missing, 'orphan:', orphan);
"
```

Visual smoke test in the browser:

1. Page renders identically to before (toggle defaults to EN).
2. Click the globe. All tagged content switches to Spanish; untagged content (chapter blurbs, tutor names, etc.) stays English.
3. Reload — Spanish persists. `localStorage.language === "es"` in DevTools.
4. Cross-page: navigate to another page that has the toggle — it should also be in Spanish.
5. Toggle dark mode while in Spanish — both prefs persist independently.
6. Open mobile viewport / hamburger menu — confirm mobile toggle works.
7. Disable JS in DevTools and reload — page must still render fully in English.

## When extending to `videos.html` next time

Expected work, in order:

1. Read the file to inventory translatable strings (likely: nav, page title, hero/intro heading + lede, the video list/grid intro labels, footer). The 6-step pattern above tells you what to do.
2. Insert the desktop navbar button and the mobile-menu row as shown above. The navbar HTML in `videos.html` is the same `metricsAI`-style template — find the dark-mode `<button>` and put the language toggle right after it.
3. Tag elements with `data-i18n`. Reuse `nav.*` and `nav.language.label` keys verbatim. Prefix page-specific keys with `videos.*`.
4. Paste the JS block. Reuse the `nav.*` Spanish translations from `index.html` or `tutors.html` so the dictionary stays consistent. Add `videos.*` keys for the page-unique copy. Add `document.title` and `document.description` keys if the page should have a translated meta description.
5. Run the verification snippet above. Open the page in the browser. Toggle. Reload. Navigate to `index.html` and confirm Spanish persists.

If you ever need to add a new section to a page that's already translated, the flow is even simpler: just add `data-i18n="some.new.key"` to the new element(s) and add the matching entries to the Spanish dictionary in that file. No JS changes needed.
