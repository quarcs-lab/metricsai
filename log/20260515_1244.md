## What shipped

### `web-apps/_shared/i18n-config.js`

Single source of truth for the language list. To add Japanese later, edit just this file:

```js
window.I18N_CONFIG = {
  languages:   ["en", "es"],   // append "ja" here
  defaultLang: "en",
  storageKey:  "language"
};
```

### `web-apps/_shared/i18n-runtime.js`

The shared runtime that every page will load via `<script src>`. Defines (all on `window`):

- `I18N` — `{ strings: { "key": { en: "...", es: "..." }, ... } }`
- `I18N_REGISTER(table)` — called by every `_shared/strings/*.js` to merge entries
- `t(key, vars)` — looks up the active language; interpolates `{name}` placeholders; falls back to `defaultLang` then to the bare key
- `applyLanguage(lang)` — persists to `localStorage["language"]`, swaps every `[data-i18n]` element, refreshes `#siteLanguageLabel`, re-fires every registered `window.__rerender_*`
- `toggleLanguage()` — cycles through `I18N_CONFIG.languages` (works for any number of languages)

Boot is two-stage:

1. **Synchronous** — reads `localStorage` and sets `window.__lang` immediately, so chapter widget IIFEs that call `t(...)` on first paint render in the persisted language with no flash.
2. **DOMContentLoaded** — runs `applyLanguage()` once the DOM exists, swapping `[data-i18n]` HTML elements and re-firing widget renderers.

### `web-apps/_shared/glossary/canonical-terms.md`

Authoritative cross-language glossary. 13 sections (site chrome, UI strings, chapter titles, descriptive stats, regression & inference, heteroscedasticity & robustness, regression diagnostics, logs/transformations/interactions, indicators/categoricals, panel/causal/IV, charting, correlation, house-data variables). Each row has `EN | ES | JA | Notes`. ~200 terms. The three vocabulary normalizations from the previous session (`heterocedasticidad`, `FAC`, `VI`) are encoded as canonical here, with explicit "NOT X" notes to prevent drift.

### `web-apps/_shared/glossary/style-notes.md`

Per-language tone/voice guidance. ES section is complete (informal "tú", HTML-tag preservation, currency/units, acronym policy, common pitfalls). JA section is a stub for the upcoming rollout. The file ends with a copy-pasteable subagent prompt template that points subagents at both glossary files plus the strings file to translate.

### `scripts/i18n_check.py`

Validation tool. Walks `web-apps/_shared/strings/*.js`, parses every `I18N_REGISTER({...})` block, and verifies:

1. Every key has a value for every language in `I18N_CONFIG.languages`.
2. No key is defined in more than one strings file.
3. Every `data-i18n="..."` attribute and `t("...")` call in any migrated HTML page references a defined key.
4. Every defined key is referenced (orphans flagged as warning, not failure).

Returns 0 on clean, 1 on issues. Subagents will be required to run it before reporting completion. Tested empty-state today: returns 0 cleanly with no strings files yet.

## Key data points discovered while preparing Phase 2

- The 17 chapters' `nav.*` keys are a **mix of site-nav (truly shared) and per-chapter widget anchor links**. Only 11 nav keys are shared across all chapters; per-chapter ones (`nav.stats`, `nav.scatter`, `nav.predict`, etc.) stay in chapter-specific files.
- Two chapters (ch13, ch17) have unicode-escaped strings (`'Regresi\\u00f3n'` instead of `'Regresión'`). Renders identically; just needs normalizing during extraction.
- `header.badge` differs across chapters by chapter number (e.g., "Chapter 02 of 18 · ..."). The migration script will need to either rewrite each chapter's badge to use interpolation (`t("header.badge", {n: "02"})`) or keep `header.badge` per-chapter. Recommend interpolation — fewer keys, cleaner glossary.
- ch01 is the cleanest reference (the hand-prototyped one). ch02–ch17 went through the navbar migration script and have minor formatting variations.
