Phase 3 of the multi-language refactor (plan: `~/.claude/plans/in-the-navigation-bar-crystalline-castle.md`). Migrate `index.html` (2600 lines) and `tutors.html` (790 lines) from per-page inline `translations.es` dicts + per-page `applyLanguage`/`toggleLanguage` helpers to the shared runtime (`web-apps/_shared/i18n-runtime.js`) + shared string tables (`web-apps/_shared/strings/*.js`) shipped in Phase 1 and Phase 2.

## What shipped

### `web-apps/_shared/i18n-runtime.js` — small additive tweak

Old: updated a single `#siteLanguageLabel` element. New: updates **every** element matching `#siteLanguageLabel` OR `[data-lang-label]`. Backwards compatible — chapter dashboards (which use the ID) keep working unchanged. Top-level pages have a desktop AND mobile language label and now use the attribute on both.

### Two new per-page string tables

| File | Keys | Purpose |
| --- | --- | --- |
| `web-apps/_shared/strings/index.js` | 52 | hero/about/curriculum/books/authors/resources/footer + `index.document.title` |
| `web-apps/_shared/strings/tutors.js` | 92 | hero/featured/8 tutor cards/how-it-works/footer + `tutors.document.title` + `tutors.document.description` |

Total registry now: **189 keys across 6 string files**.

The 17 `webapps.chNN` keys that previously lived in `index.html` (Web Apps dropdown labels) were collapsed into the canonical `chapter.chNN.title` keys from Phase 2 — values matched verbatim, so all 34 dropdown HTML references (desktop + mobile drawers) were rewritten in place: `data-i18n="webapps.chNN"` → `data-i18n="chapter.chNN.title"`.

`document.title` and `document.description` were namespaced per page (`index.document.title`, `tutors.document.title`, `tutors.document.description`) since the values differ per page and the validator forbids duplicate keys.

### `index.html` and `tutors.html` migrations

Both pages now load (in `<head>`):

```html
<script src="web-apps/_shared/i18n-config.js"></script>
<script src="web-apps/_shared/i18n-runtime.js"></script>
<script src="web-apps/_shared/strings/nav.js"></script>
<script src="web-apps/_shared/strings/common.js"></script>
<!-- index only: --> <script src="web-apps/_shared/strings/code.js"></script>
<!-- index only: --> <script src="web-apps/_shared/strings/chapter-titles.js"></script>
<script src="web-apps/_shared/strings/{index|tutors}.js"></script>
```

(Tutors doesn't reference `code.*` or `chapter.*` keys; they're omitted to avoid pointless bytes.)

The big inline `const translations = { es: {...} }` block, the inline `applyLanguage(lang)` (~40 lines), `toggleLanguage()` (~5 lines), and the boot IIFE (~10 lines) are all gone — replaced by ~3 small `__rerender_*` registrations per page:

- **index.html:** `__rerender_documentTitle`, `__rerender_heroTyped`, `__rerender_resourceFilters`. Net diff: −197 lines, +70 lines = **−127 lines**.
- **tutors.html:** `__rerender_documentTitle`, `__rerender_metaDescription`. Net diff: −193 lines, +27 lines = **−166 lines**.

The button `onclick="toggleLanguage()"` keeps working because the runtime puts that function on `window`. Both `#languageLabel` and `#languageLabelMobile` spans got a `data-lang-label` attribute so the runtime updates both on every switch.

`renderFilterPills()` and the hero typed animation in index.html were touched only minimally: replaced two reads of `document.documentElement.lang` with `window.__lang` (the runtime sets it synchronously before any IIFE runs, eliminating the brief first-paint flicker that the old code had).

### `scripts/i18n_check.py` — call_re widened

Old regex `\bt\(\s*"([\w.\-]+)"` only matched `t("key")` with double quotes. Widened to `(?:\bwindow\.)?\bt\(\s*['"]([\w.\-]+)['"]` so it also catches `window.t('key')` (the new pattern used by the page-specific renderers).
