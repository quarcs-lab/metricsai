# 2026-05-15 09:44 — Translate Web Apps Dropdown Chapter Titles to Spanish

## Issue
After commit `a39a46d` shipped the Web Apps dropdown, the dropdown's button label translated to "Aplicaciones Web" when the language toggle was set to ES, but the **17 chapter titles inside the dropdown stayed in English** in both languages. A Spanish-speaking visitor toggling to ES still saw "Analysis of Economics Data", "The Sample Mean", etc.

## Work Done
- Tagged each of the 17 chapter-title `<span>`s in the **desktop** Web Apps dropdown with `data-i18n="webapps.chNN"` (lines ~325–341 in `index.html`).
- Tagged each of the 17 chapter-title spans in the **mobile** Web Apps collapsible the same way (lines ~388–404). Mobile rows previously rendered the title as bare text — wrapped each in a new `<span data-i18n="webapps.chNN">…</span>`.
- Added 17 corresponding entries to the `translations.es` dictionary in `index.html`, immediately after the existing `nav.webapps` key (around line 2076). Vocabulary aligns with the existing `curriculum.part2`/`part3` translations (`Regresión bivariada`, `Regresión múltiple`).
- Chapter-number chip (`Ch 1`, `Ch 2`, …) is **left in English in both languages** by design — short, language-neutral, and translating it would have meant either rebuilding the HTML row structure or adding 17 more dictionary keys for a marginal win.

## Why no JavaScript change was needed
`applyLanguage()` at `index.html:2173` already iterates over every `[data-i18n]` element on every toggle, snapshots the original `innerHTML` lazily on first run via `dataset.i18nOriginal`, and swaps in the translated string. New `data-i18n` elements are picked up automatically — no registration step.

## Verification (run from project root)
- `grep -c 'data-i18n="webapps\.ch' index.html` → **34** (17 desktop + 17 mobile)
- `grep -cE "'webapps\.ch[0-9][0-9]'" index.html` → **17** (one ES entry per chapter)
- `grep -c "web-apps/ch.*/dashboard.html" index.html` → **51** (unchanged: 17 chapter cards + 17 desktop dropdown + 17 mobile dropdown)
- Node JS-syntax check on the `translations.es` block: parses cleanly, 81 keys total.

## Deployment
The translations existed locally for one full session before this commit but were never pushed — the user reported "not working" on the live GitHub Pages site, which was still serving `a39a46d`. This commit is what makes the translations visible at `https://quarcs-lab.github.io/metricsai/`.
